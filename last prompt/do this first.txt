On the laptop:

git clone https://github.com/thejoenalist/V2Earth.git
cd V2Earth/v2-starter
npm install

Then create v2-starter/.env.local by hand with four values:

VITE_CESIUM_ION_TOKEN=...    # ion.cesium.com → Access Tokens
VITE_SUPABASE_URL=...        # Supabase → Project Settings → API
VITE_SUPABASE_ANON_KEY=...   # same page (anon/public key — safe in browser)
ANTHROPIC_API_KEY=...        # console.anthropic.com — DEV ONLY, used by the
                             # local parse proxy; never reaches the browser

Easiest is to copy the values from the .env.local on this machine. Don't paste them into chat, email, or a commit — the Anthropic key especially, since it bills your credits. A password manager note or a USB copy is fine.

Then npm run dev → localhost:5173.

Two gotchas specific to this project:

Cesium ion tokens are scoped per-token, so if you generate a new one rather than reusing the existing token, give it access to asset 1 (World Terrain) and OSM Buildings, or terrain silently falls back to a flat ellipsoid.

Python is only needed for the data pipeline (pipeline/), and you almost certainly don't want to run it locally — the bakes run in GitHub Actions and need DEM downloads. Skip it unless you're editing pipeline code.

The thing that will actually bite you: working across two machines. Today's rebase mess (that duplicate flyToISO) came from main moving ahead while you worked. Habit to adopt: git pull before you start on either machine, push before you stop. If you ever see "remote had moved ahead" again, diff the result before trusting it.
